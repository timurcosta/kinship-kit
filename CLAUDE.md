# Семейные исследования

Здесь лежат генеалогические дела, по одному на линию (например, `papina-liniya/`, `mamina-liniya/`).

У каждого дела своё состояние в `research-state.md`. Продолжать с него, а не начинать заново. Если в деле есть свой `CLAUDE.md`, сначала прочитать его.

## Навыки

- `ex-ussr-kinship-research` — само исследование: реестры, доказательства, отчёт, PDF. Это чужой навык из репозитория автора (github.com/DenisSergeevitch/ex-ussr-kinship-research), его файлы не править. Его ошибки обходить своими обёртками.
- `kinship-site` — живой сайт из готового отчёта: карта, документы, хронология, версии, выкладка через `git push`. Один движок на все дела, в деле только данные.

## Не отмазываться: сначала всё онлайн (главное правило)

Письмо в архив, бумажный запрос, «приложите свидетельство о смерти», поездка — это **не конец исследования, а параллельная ветка**. Её оформить и тем же ходом продолжать поиск онлайн.

- **Ответ «дальше только офлайн / нужно написать в N мест» запрещён**, пока не пройден онлайн-чеклист ниже и каждый пункт не записан в журнал поиска (`search-log`) с результатом: нашли / не нашли (каким запросом, какие формы фамилии) / заблокировано (капча, вход, недоступно из страны).
- **Письма — только черновики** в `requests/` и пункт в разделе отчёта «Что может сделать семья». В ответе пользователю их не перечислять как «следующие шаги». Показывать этот список, только когда пользователь спросит про офлайн.
- **«Что дальше?»** — только то, что делается онлайн: субагенты, браузер, базы, API, каталоги, OCR-поиск по сканам.
- **Свидетельство о смерти и доказательство родства** нужны для персональных дел из закрытых фондов (ЗАГС младше 100 лет, личные дела, ФСБ/МВД). Метрики старше 100 лет, ревизские сказки, базы ВОВ, журналы боевых действий, наградные, приказы, карты, трофейные немецкие документы, книги памяти, списки репрессированных открыты без него. Их пройти до конца.
- **«Не нашли» — только после контроля.** Прогнать контрольный запрос по заведомо известной записи (базы бывают пусты целиком), перебрать формы фамилии (старая орфография, искажения писаря, ё/е, -ов/-ев/-ин, девичьи), годы ±2–3, без отчества, по месту призыва/рождения вместо фамилии.
- **Не нашли человека — ищи его окружение.** Однополчан того же военкомата и даты призыва, часть по соседним записям, журнал боевых действий части за даты, донесение о потерях целиком (там место захоронения), наградные приказы целиком (в индексе часто один человек, остальные только на скане), соседей по селу в метриках и ревизиях.
- **Пропал без вести ≠ тупик.** Цепочка: ОБД → донесение о безвозвратных потерях части (дата, место) → журнал боевых действий и отчётные карты за эти дни → немецкие трофейные документы (карточки военнопленных в ОБД, ЦАМО ф. 500) → перезахоронения и братские могилы в районе (ОБД «захоронения», сайты мемориалов, местные книги памяти) → «тогда и сейчас» на современной карте.
- **Вход и капча — делает пользователь**, а пока продолжать другие маршруты.
- **Исследование вести субагентами**: независимые маршруты раздавать параллельно, главная сессия координирует, проверяет и сохраняет.

### Онлайн-чеклист по типу задачи

- **Репрессии, раскулачивание, депортации**: ru.openlist.wiki («Открытый список»), lists.memo.ru, bessmertnybarak.com, региональные книги памяти жертв репрессий.

- **Место**: старое название → нынешнее через Википедию, справочники АТД, OSM Nominatim, старые карты (РККА, трёхвёрстка).

## Конец раунда: онлайн-план и передача дальше

Цель — чтобы поиск шёл дальше сам и пользователю не приходилось подталкивать.

- **Когда.** Исполнители раунда закончили, итоги проверены и записаны, или контекст сессии подходит к концу. Вопроса «что дальше?» не ждать.
- **Что сделать.** Тем же ходом составить онлайн-план следующих действий, по убыванию пользы. Копать широко, не только главный вопрос:
  - человек: служба, ранения, награды, плен, захоронение, однополчане и земляки;
  - род: родители, братья и сёстры, супруги и их семьи, дети, предки до метрик и ревизий;
  - место: село, приход, сельсовет, соседи по записям;
  - каждый открытый вопрос из `research-state.md` и каждый пункт «не доделано» из итогов исполнителей.
- **Каждая задача в плане:** что ищем и зачем, где (база, фонд, шифр), что уже исчерпано, рабочие приёмы, модель исполнителя, ожидаемая польза.
- **Куда записать.** План — в `<дело>/online-plan/NEXT-SESSION.md`. Файл должен быть самодостаточным: правила, состояние, что исчерпано, задачи по приоритету, следующие свободные номера в реестрах, как собрать отчёт и сайт, и фраза для запуска новой сессии.
- **Кому отдать.**
  - Есть параллельная сессия (видна в `ListAgents`) — отправить ей план через `SendMessage`. Договориться о буквах исполнителей, номерах в реестрах и о том, кто проверяет сканы и пишет в реестры, отчёты и на сайт.
  - Параллельной сессии нет — дать пользователю одну фразу для новой сессии (или для `/loop`).
- **Сессия, которая получила план, работает волнами до конца:** запустила задачи → проверила и записала итоги → обновила план → сразу следующая волна.
- **Когда останавливаться:** капча или вход, нужно решение пользователя, онлайн-задач не осталось. В последнем случае показать журнал поиска.

## Отчёты и доказательства

- Каждое новое или изменённое сведение в отчёте подкреплять доказательством: документ, скан, фото, страница базы.
- В PDF рядом с выводом ставить мини-скрин (вырезку строки или фрагмента) со ссылкой «полностью — Приложение N». В приложении документ целиком.
- **Объяснять вывод простыми словами.** Читатель не военный и не архивист. У каждого вывода из сложного документа (карта, журнал, таблица):
  - короткое «по шагам»: где нашли и кто составил документ; что там буквально написано; как это читать (сокращения, значки, цвета); как старое название сопоставлено с нынешним местом; какой второй документ это подтверждает; чего мы не знаем;
  - картинка документа с пронумерованными пояснениями к пометкам;
  - для мест — «тогда и сейчас»: та же местность на сегодняшней карте.
- Расшифровкам (своим, субагентов, расширения) не верить вслепую: спорный скан читать самому.

## Пожелания пользователя сохранять

Если пользователь просит что-то общего характера, записывать это тем же ходом:
- пожелание к сайтам — в раздел «Пожелания пользователя» в `~/.claude/skills/kinship-site/SKILL.md`;
- пожелание к исследованию или общению — сюда;
- пожелание только для одного дела — в `CLAUDE.md` этого дела.

**Найденные приёмы сохранять для всех сессий.** Удобный шорткат, обход ошибки сайта, внутренний API, грабли инструмента — записывать тем же ходом, без отдельной просьбы, коротко: что делать и почему так. Субагентам в задании просить раздел «Приём для CLAUDE.md» и переносить его сюда.

## Общение и правила

- Отвечать по-русски. Цитаты из источников давать в оригинальном написании.
- **Капчи и вход.** Капчи не обходить. Вход и капчу делает пользователь. Если сайт показал капчу или «сбавьте скорость», не заходить на него другим инструментом (WebFetch, `curl`, мобильная версия, другой адрес): это тоже обход. Субагентам писать это в задании.
- **Письма** в архивы и ведомства — только черновики в `requests/`. Отправлять только по явному «отправляй». Почтовые серверы некоторых российских госорганов отвергают Gmail (`554 5.7.1 Sender address rejected`): тогда письмо уходит с российского ящика (mail.ru, Яндекс).
- **Живые люди.** О живых — минимум: имя и роль в семье, без адресов и контактов.
- **Выгрузка в интернет.** Семейные документы и фото — только с явного согласия: сайт по секретной ссылке, приватный репозиторий.
- **Ключи.** Ключи и токены не печатать.

## Субагенты и модели

- Независимые маршруты поиска — субагентам параллельно. Файлы в дело субагенты не пишут: полный отчёт возвращают сообщением, реестры и сканы сохраняет главная сессия.
- Браузер: расширение Claude in Chrome, каждый субагент в своей новой вкладке, не больше двух одновременно.
- **Opus** — где нужна голова: рукописные сканы, спорные записи, однофамильцы, оценка доказательств, незнакомый источник, отчёт и письма.
- **Sonnet** — механика по готовому приёму: выгрузки через API, перебор форм фамилии и сёл, листание описей, сбор ссылок, вырезки, сверка CSV.
- Спорную запись, найденную Sonnet, читает Opus или главная сессия.
- Большие сканы давать вырезками строк 150–200 px, увеличенными в 3–4 раза: целые кадры по 4000 px часто не доходят.

## Приёмы для баз данных о войне

- **ОБД «Мемориал».**
  - Поиск открывается адресом `search.htm?pb=T~<слово>&entity=000000011111110&entities=24,28,27,23,34,22,20,21&ps=100&p=N`. `pb` ищет только целые слова, поэтому каждую форму фамилии передавать отдельно.
  - Если `pb=T~` пустой, работает адрес формы с главной: `search.htm?f=<фамилия>&n=<имя>&s=<отчество>&y=<год>&r=`.
  - Перед выводом «нет» — контрольный запрос по заведомо известной фамилии.
  - Скан открывать в отдельной вкладке по адресу картинки (`images3?id=…`), затем canvas → dataURL.
- **«Память народа».** Показывает капчу автоматическому Chrome — работать через расширение Claude in Chrome в обычном браузере пользователя.
  - **API сайта** (быстрее формы, до 100 записей за запрос): только из открытой вкладки pamyat-naroda.ru, `fetch` POST на `/entrypoint/api/` с заголовками `X-Csrf-Token` (из скрытого поля `input[name=csrf]`), `Accept: application/json`, `X-Requested-With: XMLHttpRequest`. Тело: `{"entrypoint":"heroes/search","parameters":{"query":{…},"page":N,"size":100,"groups":[…],"options":{"person":true}}}`; поля `query` подсмотреть в запросе самой страницы поиска. Из `curl` нельзя: нужны сессия и токен страницы.
  - Все записи одной части за нужные месяцы: `division_ids:[<id>]` + `vibitiye_date_from`/`vibitiye_date_to` (`YYYY-MM-DD`). Фильтр нестрогий, досеивать по `data_vibitiya`.
  - Одна фамилия ищется нечётко, а `last_name` + `birth_place` — строго.
  - Расширение обрезает вывод примерно до 1000 символов и не печатает строки со словами token/csrf/cookie и символами `=&?`: результат класть в `window.…`, читать порциями, перед выводом `.replace(/[=&?]/g,'.')`.
  - Не больше ~5 больших выгрузок подряд, с паузами, иначе капча.
  - **Документы частей**: если `documents/view/?id=magazine…` пустой, открывать `?id=<число>`. Форма «Уточнить» (автор + даты) отдаёт пустую выдачу из-за ошибки сайта: свой `fetch` POST на `…/army_unit_document/_search` (адрес из `performance.getEntriesByType('resource')`), например `{"query":{"bool":{"must":[{"term":{"fond":"229"}},{"range":{"date_from":{"lte":"1942-07-15"}}},{"range":{"date_to":{"gte":"1942-07-01"}}}]}}}`. Так находятся все документы фонда за нужные дни, включая карты.
  - «Боевые операции» → «Исторические карты»: советские отчётные карты фронтов с привязкой (сдвиг бывает 2–3 км, координаты брать из OSM).
  - **Наградные приказы читать целиком**: соседние страницы — соседние номера файлов картинки.
  - **Списки запасных полков**: в фонде запасного полка `army_unit` ищет по графе «куда выбыл» — сразу видно, кого отправили в нужную часть.
  - Сохранить скан: из вкладки ПН `fetch` → blob → `<a download>`, потом взять из `~/Downloads`.
  - Скан в «Книгах памяти» иногда сам раскрывает искажённую фамилию («Ибрагимав(Ибрагимов)»).
- **Немецкие трофейные документы** (wwii.germandocsinrussia.org, ЦАМО ф. 500): поиск `ru/nodes/search?query=…`. Карты — OpenLayers, объект `window.map`, страница `ru/pages/<id>/map`.
- **«Открытый список»** ограничивает темп чтения («Подождите 280 секунд»): анкеты по одной с паузами; пустой ответ = лимит, а не «нет данных».
- **«Бессмертный барак»**: `curl -X POST https://bessmertnybarak.com/ -d post_name=search -d query=<фамилия> -d section=books -d page=N`.
- **Кодировка.** Сайты в cp1251 читать через `curl` с перекодировкой: WebFetch их портит.

## Приёмы для архивных порталов

- **FamilySearch** (вход делает пользователь). Снимок плёнки: `…/search/film/00XXXXXXX?i=N`, где `i` = номер снимка − 1. Full-Text кириллицу не индексирует. Без входа зеркало каталога — nashipredki.com/familysearch/<номер> (капча на частые запросы).
- **FamilySearch Family Tree.** Без `q.surname.exact=on` выдача тонет в мусоре; с ним работают маски `q.surname=*ivan*&q.surname.exact=on&count=100`. Выдача дорисовывается 4–6 с.
- **Geni** без входа: `/search?search_type=people&names=<имя фамилия>&page=N`.
- **WikiTree** — открытый API: `api.wikitree.com/api.php?action=searchPerson&LastName=…`.
- **Яндекс «Поиск по архивам».** Каталог виден без входа (`__NEXT_DATA__`, `&pageNum=N`, оцифровку показывает `is_digitized`). **Поиск по распознанному тексту работает без входа**, со сниппетами: `ya.ru/archive/search?text=…&archiveId=<id>&fundId=<id>&searchZone=name%3Bsheet&index=archive`; внутри дела — `&fileId=<id>`. XVIII век распознан плохо, заголовки XIX века — хорошо: удобно искать по названию деревни. Сканы — после входа пользователя.
- **Wayback**: не чаще 1 запроса в 5–7 с; `curl -sL https://web.archive.org/web/2020/<url>` работает, когда WebFetch нет. Список снимков: CDX API. Через Wayback читать сайты, которые не открываются из твоей страны.
- **ВКонтакте** (расширение, пользователь залогинен): поиск сообществ района/села, поиск по стене `vk.ru/wall-<id>?q=…`. Не больше 10–15 переходов за заход.
- **Если сайт не открывается** (часть российских госсайтов недоступна из-за рубежа) — пробовать через расширение Claude in Chrome или Wayback, иначе просить пользователя.

## Инструменты (macOS)

- Картинки: `sips` (обрезка `-c H W --cropOffset y x`, уменьшение `-Z`).
- Текст и картинки из PDF: venv в scratchpad (`python3 -m venv v; v/bin/pip install pypdf pymupdf`).
- Headless Chrome не завершается сам: после появления файла делать `pkill` по пути своего профиля, чужие процессы не трогать.
- Python с кириллицей в heredoc: `python3 -X utf8`. Файлы из интернета обрабатывать с `python3 -I`.
