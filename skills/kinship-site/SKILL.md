# Семейный сайт из отчёта

Один движок на все дела. В деле лежат только данные (`site.json`, `story.json`, текст отчёта, сканы), а сборщик, оформление, карта и выкладка живут здесь. 

Отчёт и PDF делает навык `ex-ussr-kinship-research` (шаг 12, `pdf-source/report.html`). Этот навык начинается, когда отчёт уже есть.

## Что получается

- **Главное**: лид отчёта карточками, семейное фото, кнопки «карта», «документы», «PDF».
- **Семья**: дерево по поколениям; нажатие на человека показывает его место на карте.
- **Карта** (Leaflet, работает без интернета):
  - несколько видов, например «Семья», «Июль 1942»;
  - значки по типам мест и фильтры по ним;
  - путь по датам с плеером;
  - слой фронта: стрелки немецких ударов, котёл, прорыв;
  - всплывающие окна со ссылками на документы.
- **Документы**: все рисунки отчёта по разделам; просмотр с увеличением, свайпом и пальцами.
- **Хронология**: собирается из таблицы раздела «Хронология» в отчёте и шагов пути.
- **Отчёт**: полный текст, оглавление и поиск с подсветкой.
- **История версий**: версиями становятся только обновления с новыми сведениями; правки вида присоединяются к ним. Версию можно открыть целиком или посмотреть, что добавлено и что убрано.
- Подходит для телефона, проверено на ширине 390px.
- **Несколько линий и языков на одном сайте** (например, отцовская и материнская линии, русский и грузинский):
  - общее дерево, где у каждой линии свой цвет, и карточки линий на главной;
  - переключатель линий под шапкой меняет карту, путь по датам, документы, хронологию и отчёт; общие виды карты показывают обе линии сразу;
  - у каждой линии свой `report.html`, он может лежать в другом деле (`../chkhaidze/pdf-source/report.html`); PDF копируются в `web/pdf/`;
  - первый язык — `index.html`, остальные — `<lang>.html`; кнопка в шапке, выбор запоминается;
  - подписи интерфейса — в `assets/ui.json` (ru, ka); для нового языка добавить туда словарь.

## Порядок работы

Пути ниже даны от папки дела; `$K` — это `~/.claude/skills/kinship-site/scripts`.

1. **Подготовка, один раз на дело**: `python3 -I $K/init_site.py . --surname-latin <фамилия-латиницей, например ivanovy> --github-user <login>`.
   - Создаёт заготовки `site.json`, `story.json`, `make_maps.py`, `.gitignore`-whitelist и `deploy.yml`.
   - Существующие файлы не трогает.
2. **Карты Natural Earth, один раз на машину**: `zsh $K/fetch_naturalearth.sh`, около 40 МБ в `~/.cache/kinship-site/naturalearth`.
3. **Данные**: заполнить `site.json` и `story.json` (поля — в `references/config.md`).
   - Координаты: `python3 -I $K/geocode.py .`. Это Nominatim: не чаще 1 запроса в секунду, ответы кэшируются. Каждую точку проверить глазами: одноимённых сёл много.
   - Если место нашлось неточно или исчезло, задать его в `placeOverrides`.
4. **Сборка**:
   - статические карты для PDF: `python3 -I pdf-source/maps/make_maps.py ~/.cache/kinship-site/naturalearth pdf-source/maps/geocode.json pdf-source/maps`;
   - PDF: `zsh $K/build_pdf.sh .` (обходит зависание headless Chrome);
   - сайт: `python3 -I $K/build_web.py .`.
5. **Просмотр**: `zsh $K/preview.sh .` → http://localhost:8765/.
   - Проверить в chrome-devtools на компьютере и на телефоне: `emulate viewport "390x844x3,mobile,touch"`.
   - Смотреть, чтобы подписи не налезали, не было горизонтальной прокрутки и ошибок в консоли.
   - Показать пользователю. **Без его «пушим» не выкладывать.**
6. **Выкладка**: `git add -A && git commit -m "<что изменилось, по-русски>" && git push`. Потом `gh run watch` и проверка `curl` живого сайта.
   - Сообщение коммита становится названием версии на сайте, его читает семья. Писать человеческим языком: «Добавлено объяснение, почему в документах он «Иванец», а она «Иванцова»».
   - Неудачное старое название исправляется в `pdf-source/web/version-notes.json` (`{"<sha7>": "название"}`), историю git не переписывать.

### Хостинг для нового дела, один раз

Внешние шаги делает пользователь или выполняют с его явного согласия. Классификатор Claude Code блокирует их, даже когда пользователь сказал «да», поэтому отдавать ему готовые команды:

1. `gh auth login`, вход делает пользователь.
2. `gh repo create <repo> --private --source . --remote origin --push`. Перед этим проверить `git status`: в git должны попасть только `web/`, PDF, `pdf-source/` и `.github/`.
3. `zsh $K/setup_hosting.sh .`, запускает пользователь. Скрипт:
   - создаёт бакет (публичное чтение без листинга, режим сайта, лимит 200 МБ);
   - создаёт сервисный аккаунт с правами только на этот бакет;
   - кладёт ключ прямо в секреты GitHub, не выводя его;
   - запускает деплой.

Запасной путь без GitHub: `zsh $K/publish_manual.sh .`.

## Правила

- **Приватность.**
  - `.gitignore` — whitelist. Реестры, `inputs/`, переписка, черновики писем в архивы и оригиналы сканов остаются на машине.
  - Сайт открывается по секретной ссылке, в нём `noindex` и `robots.txt`.
  - Выкладывать в интернет только с согласия пользователя: это семейные документы.
  - Для живых людей минимум сведений: имена и роли в семье, без адресов и контактов.
- **Честность карты.**
  - Каждое событие и каждая стрелка несут пометку `tag`: `ok` — по документу, `maybe` — вероятно или схема, `fam` — по сведениям семьи.
  - Стрелки противника и границы котла — всегда схема. Их пометка `maybe`, если источник — общая история, а не документ дела, и в `src` так и написано.
- **Понятность «простым людям».**
  - Значок должен читаться без легенды: танк, наручники, флаг.
  - Не перегружать карту.
  - Подписи короче на телефоне (`short`); если наложились, развести их (`dir`, `centerNarrow`).
- **Безопасность.** Не печатать ключи и токены. Не трогать чужие бакеты в облаке пользователя.
- **Найденные приёмы записывать сюда** (пожелание пользователя, 29.10.2026). Обход ошибки движка, карты, сборки или выкладки, о котором раньше не знали, записывать в этот раздел тем же ходом, коротко: что делать и почему. Приёмы для архивов и сайтов-источников — в `CLAUDE.md` папки с делами.

## Пожелания пользователя к семейным сайтам

Это решения, которые пользователь уже принял. Они действуют для всех дел. **Когда пользователь высказывает новое пожелание общего характера («сделай, чтобы…», «не нравится, что…»), записать его сюда тем же ходом**, вместе с изменением кода. Пожелание, которое касается только одного дела, записывать в `CLAUDE.md` этого дела.

- **Название рода — по нынешней фамилии семьи.** «Ивановы», а не «Ивановичи» из старой метрики. Это касается заголовка, логотипа, адреса сайта (имени бакета), репозитория и имени PDF. Документальные формы (как записан прадед) оставлять там, где речь о самом документе.
- **История версий — только для важного.**
  - Версия = появились или поменялись сведения: текст отчёта, люди, места, события, подписи на карте.
  - Правки вида (стрелки, значки, вёрстка, движок) отдельной версией не показываются, это делает `stage_public.py`.
  - Название версии говорит, что нового узнали, а не что поправили в коде.
- **Карта понятна родственникам без легенды и не перегружена.**
  - Противник — синие стрелки с танком; окружение — красный пунктирный «котёл»; прорыв — пунктирная стрелка.
  - Значки должны узнаваться сразу. Для плена — наручники; решётку, замок, колючую проволоку и человечка с поднятыми руками пользователь отверг.
  - Мелкие огрехи формы (зубцы на наконечниках, кривые наконечники) пользователь замечает. Проверять при увеличении.
- **Сначала показать, потом выкладывать.** Локальный просмотр со скриншотами компьютера и телефона, увеличенный вид мелких значков, затем ждать «пушим».
- **Каждая находка подкреплена доказательством, и его видно рядом.**
  - На сайте у вывода есть документ, фото или скан, который открывается в просмотре.
  - В PDF рядом с находкой стоит мини-скрин: вырезка нужной строки или фрагмента со ссылкой «полностью — Приложение N». В приложении документ целиком.
  - Не сваливать все сканы только в конец.
- **Офлайн-задачи — на сайте, а не в чате.** Всё, что семья может сделать сама (письма в архивы, расспросы старших, фото памятников, чтение старых книг), живёт в разделе отчёта «Что может сделать семья» с инструкциями и ссылками на черновики. Раздел обновляется с каждой версией. Если инструкций много, можно приложить PDF или отдельную страницу.
- **Ссылки не ломать.** При смене адреса старый бакет перенаправляет на новый (`redirect_all_requests`), чтобы разосланные ссылки работали.

## Где что лежит

- `scripts/build_web.py` — сборщик `web/` из `report.html`, `site.json`, `story.json`, `geocode.json` и Natural Earth (картинки через macOS `sips`).
- `scripts/stage_public.py` — публичная копия:
  - снимки версий из истории git в `v/<sha7>/`, плюс `versions.json` и `sections.json` для сравнения текста;
  - копия лежит в деле, потому что нужна CI; `build_web.py` держит её в актуальном виде.
- `scripts/maplib.py` — статические SVG-карты для PDF. В деле `make_maps.py` только раскладывает места.
- `assets/ui.json` — подписи интерфейса по языкам (ru — исходные, ka — грузинские); сайт может переопределить их в `site.json` → `ui`.
- `assets/app.js`, `assets/app.css` — сайт. В `app.js` есть рисунки значков (`GLYPH`), их пары лежат в `maplib.glyph`.
- `assets/deploy.yml`, `assets/gitignore` — шаблоны для `init_site.py`.
- `references/config.md` — все поля `site.json` и `story.json`, включая слой фронта.
